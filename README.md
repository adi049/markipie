# MARKIPIE — Wedding & Event Photography Platform

Premium multi-page photography platform: public marketing site, private AI-powered
client galleries, collage maker and a studio admin console.

Zero runtime dependencies — plain Node.js (`http`) + JSON file storage.

---

## Run

```bash
cd /home/user
node migrate.js      # first run only — migrates data, prints an admin password
node server.js       # http://localhost:3000
```

`npm start` also works. Production:

```bash
NODE_ENV=production ADMIN_PASSWORD='a-long-password' node server.js
```

Dev QA dependencies (`playwright-core`) are optional and only used for testing.

## Admin

* URL: `/mk-admin` (discreet — linked only in the footer, `noindex`)
* Password: generated by `node migrate.js` and written to **`data/.adminpass.txt`**
  (stored as a scrypt hash in `data/.adminpass`; delete the `.txt` after noting it).
* Override with the `ADMIN_PASSWORD` env var, or change it in **Settings → Change admin password**.

## Data migration

`node migrate.js` is **idempotent** and backs up `data/` to `data/.backup-<timestamp>/` first.

1. Links every event to a `clients` record via `clientId` (creating clients where needed).
   Legacy fields are preserved.
2. Adds a canonical `permissions` object per event, derived from the old
   `allowDownload` / `allowShare` booleans.
3. Sets the four approved package tiers (₹25,000 / ₹45,000 / ₹60,000 / ₹1,25,000),
   keeping admin-edited copy (`featuresEdited` / `descEdited` flags).
4. Removes the plaintext `adminPassword` from `data/settings.json` and creates a
   scrypt-hashed credential.

## Architecture

```
server.js          routing, API, permission enforcement, static + range serving
lib/db.js          JSON store with mtime cache
lib/ui.js          shared shell/head/nav/footer
lib/pages1-3.js    page templates (home/about/portfolio/gallery | services…contact | client/collage/admin)
lib/auth.js        scrypt admin credential
lib/phone.js       Indian phone normalisation + comparison
lib/ratelimit.js   fixed-window limiter
lib/otp.js         OTP provider abstraction (MSG91/Twilio) — never fakes success
lib/drive.js       Drive listing with full nextPageToken pagination
public/js/*.js     client gallery, admin SPA, collage, gallery, forms, main
data/*.json        content + events + sessions
```

### Security model

* All permissions enforced **server-side**; the frontend only reflects them.
* Downloads go through `GET /api/client/download/:mediaId`, which verifies session,
  event ownership, media membership, per-type permission and payment status.
* The Drive proxy verifies the file belongs to the requesting session's event.
* Rate limits on access-code, phone, OTP and admin-login attempts.
* Stored phone numbers are never returned to the browser (only a masked hint).
* Drive API key and admin credential are never sent to the client.

## Publish control

`reviews`, `portfolio` and `gallery` items each carry a `published` boolean
(existing rows default to `true`, so nothing disappeared on upgrade). Unpublished
items vanish from the public site but stay editable in admin. Blogs use
`status: published|draft` and drafts also 404 and drop out of `sitemap.xml`.

## Gallery sharing (`/s/:token`)

Sharing is **token-based, not ID-based** — an event id or access code in the URL
resolves to 404. `POST /api/client/share` (authenticated client session only)
mints a 30-day random token stored in `data/shares.json` and reuses the live one
on repeat clicks. Every view of `/s/:token` re-checks, in real time:

* the token exists, is not revoked and has not expired;
* `permissions.shareGallery` is still on — turning it off in admin instantly
  kills links already handed out;
* the event is still `paid`/`partial`.

The shared page is read-only: photographs only, `noindex,nofollow`, and no
download endpoint, phone number, access code or payment status is rendered.
`POST /api/client/share/revoke` kills every link for the event.

## Scaling note

Data is JSON under `data/`, written atomically (write-to-`.tmp` + `rename`),
verified against 60 concurrent writes with no corruption. This is appropriate
for a single-studio deployment. **PostgreSQL or Supabase can be introduced later**
for multi-tenant/multi-writer production scaling; `lib/db.js` is the only module
that touches storage, so it is the single seam to swap.

## Production checklist (enforced, not advisory)

The admin credential generated by `node migrate.js` is flagged `bootstrap` in
`data/.adminpass`. While that flag is present the app **refuses to start with
`NODE_ENV=production`** and shows a warning banner on the admin dashboard.

Clear it one of two ways:

```bash
export ADMIN_PASSWORD="a long unique password"   # recommended
```
or log in and use **Admin → Settings → Change password** (which also deletes
`data/.adminpass.txt`).

`.env` is gitignored and no `.env` file is committed — copy `.env.example`.
Drive keys, OTP keys and the admin password are read server-side only and are
stripped from every `/api/admin/*` response.

## Private client media

Client/event photographs are **not** served from `public/`. They live in
`private-media/` (outside the static root) and are reachable only through:

```
GET /api/client/media/:mediaId        # authenticated gallery session
GET /api/client/download/:mediaId     # + payment & download permission
GET /api/s/:token/m/:mediaId          # read-only, valid share token
```

Each request re-checks the session, that the media belongs to that event, and
the relevant permission. Guessing a filename under `/images/` or
`/private-media/` returns 404 — the directory is never passed to `serveStatic()`.

Public site imagery (portfolio, gallery, blogs, services, packages, homepage)
stays in `public/` and is unaffected.

Face Scan reads the same authenticated URLs, so private photos are scannable
without ever being public. Responses are same-origin, so the canvas is not
tainted and descriptors can be computed.

Run `node migrate-private-media.js` once to move existing event media; it is
idempotent and skips Drive-backed records.

## Building a deployment package

```bash
node build-dist.js      # writes dist/
```

`dist/` excludes `.env`, `data/.adminpass*`, `data/.backup-*`, `node_modules`
and `package-lock.json`, and blanks runtime session files. Your working tree is
left untouched, so local backups remain available for recovery. The packaged app
ships **no admin credential** — set `ADMIN_PASSWORD` or run `node migrate.js`
on the server.

## Content management (CMS)

Every public section is stored in `data/*.json` and edited from `/mk-admin`.
There is no hardcoded content in the page templates — the public pages read the
same records the admin writes.

| Section | Visibility flag | Reorder | Notes |
|---|---|---|---|
| Portfolio | `published` | yes | 13 categories, location, date, cover + gallery images, featured |
| Packages | `enabled` | yes | price, features, popular/flagship |
| Blogs | `status` | yes | draft/published; drafts 404 and stay out of `sitemap.xml` |
| Reviews | `published` | yes | rating clamped 1–5, optional photo |
| Team | `visible` | yes | bio, Instagram/LinkedIn; a record with no name is not rendered |
| Services | `published` | yes | description + feature list |
| Albums | `published` | yes | finish, gallery images, features |
| Settings | — | — | business info only |

Run `node migrate-cms.js` once to add the CMS fields to existing records. It is
idempotent and defaults everything to visible, so nothing disappears.

**Settings holds business information only.** The server whitelists the writable
keys, so credentials (`ADMIN_PASSWORD`, `GOOGLE_DRIVE_API_KEY`, OTP keys) can
never be written through the CMS, and face-tuning values stay in their own panel.
Social URLs must start with `http(s)://` and the email is format-checked.

Static assets: JS/CSS are served `no-cache, must-revalidate` with ETags (so admin
and site updates reach returning browsers immediately, revalidating with a 304),
while images and video keep a 7-day cache.

## Portfolio project pages

Each portfolio record has a `slug` (added by `node migrate-slugs.js`, idempotent —
existing slugs are never rewritten). `/portfolio/<slug>` renders the project from
CMS data: category, location, year, description, cover and gallery images, with a
lightbox and related projects. Unpublished projects 404.

## Public content API

Read-only, unauthenticated, published-records-only JSON:

```
GET /api/content/portfolio|packages|blogs|reviews|team|services|albums|gallery
```

Each collection has a field whitelist, so drafts, hidden rows, blog bodies and
internal fields (`privateFile`, `accessLog`, client phones, selections) are never
returned. Unknown collections 404.

## Image upload

`POST /api/admin/upload?name=<filename>` with the raw image bytes as the body
(admin session required). The file type is decided by **magic bytes**, not by the
filename or Content-Type — JPG, PNG and WebP only, so SVG and disguised scripts
are rejected. Max 8 MB. Filenames are slugified and de-duplicated, and traversal
in the supplied name is neutralised.

`POST /api/admin/upload/delete` removes an asset, but **refuses with 409 while any
CMS record still references it** and names what is using it.

`/blog` and `/blog/<slug>` 301-redirect to the canonical `/blogs` URLs.
